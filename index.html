Mechanic 1

Grid inventory, playable with mouse or gamepad

Items take up shaped spaces on a grid and can be rotated, dragged between containers or dropped. Mouse players drag and drop; gamepad players move a selector that carries the item. Both paths use the same placement rules, so they can never disagree about where an item fits.

Mechanic 2

Sewer system: teleporting through the manholes

Manhole covers around the world are the game's fast travel. The player discovers and unlocks them while exploring, and opening one shows the sewer map. Confirming a destination teleports the player there: inside the same map or to another level, behind a loading screen so the jump is never visible, and onto an exit point that level designers place by tag. Unlocked manholes and the player's current one are saved with the game.

1 · DiscoverFastTravelInteractableComponent

Each manhole registers itself and plays its unlock animation the first time.

2 · ChooseUFastTravelWidget

Sewer map with every unlocked manhole, map location and preview image.

3 · ConfirmUConfirmationModalWidget

"Do you want to travel to…?", focused for gamepad.

4 · TeleportUFastTravelSubsystem

Loading screen, level change if needed, pawn placed at the exit point.

The sewer map UI

The menu never polls the travel system. It subscribes to its state changes, rebuilds the list when a manhole is unlocked, swaps the map and preview images as the player moves through the list, and gives focus back to the first usable entry when the player switches between mouse and gamepad.

Mechanic 3

HUD, menus and the input behind them

AGameHUDSetUp creates every menu and is the only place that opens or closes them: it checks whether a menu may open, tracks focus, applies toggle cooldowns and swaps to menu input while one is open. Underneath, gameplay and UI never read a key. They subscribe to delegates from the player controller, and every button prompt shows the icon for the device in the player's hands.

1 · Raw inputFInputDeviceInputProcessor

Slate pre-processor. Sees every key and mouse move before any widget, consumes nothing.

2 · DeviceUInputDeviceTrackerSubsystem

Keyboard/mouse or gamepad, and Xbox, PlayStation or Switch through Steam Input.

3 · IconsUInputGlyphService

Maps logical actions to button icons from data assets set in Project Settings.

4 · UIPrompts, tutorials, menus

Subscribe to device changes and redraw icons or restore focus on the spot.

What I would do differently

SetInputContext() clears every mapping and applies a single context, so an overlay cannot add input on top of the current mode. Next time I would use a context stack with priorities. AGameHUDSetUp also grew into one class that knows every menu; I would split it into a generic menu stack (or CommonUI activatable widgets) where new screens register themselves. The sewer map loads its preview textures synchronously, which an async load would avoid, and PlacePawnSafelyNear() teleports straight to the target instead of sweeping for a free spot within its search radius.

Mechanic 1

Customer and worker AI

Customers walk in with a shopping list, browse the shelves and specialist stalls, queue and pay. Workers are hired with their own stats and run up to three tasks (cashier, cleaning, security, restocking…), and the game decides every frame which one each worker should be doing.

Mechanic 2

UI and menus

A management game lives in its menus: hiring workers from cards, assigning their tasks by drag and drop, buying stock in the central market, the end-of-day report and the newspaper with the town's events.

Mechanic 3

Construction system

The player furnishes and expands the supermarket on a grid: shelves are previewed in green or red, rotated, paid for, placed or sold back, and every placement is saved with the game.
